# Templates

All three are empty: no concepts and no code lists. The remaining help texts ("for eksempel N101") are examples.

| File | Version | Use |
| --- | --- | --- |
| `SKOS-Excel-mal-v9-for-import.xlsx` | v9 (master) | Current template. Sheet `vokabular` with the Excel table `begrepsliste` (header row 24, data from row 25). Column B holds the concept name (key, CamelCase), generated by a formula from the bokmål term in C (Excel 365/2021); a typed name replaces it. Column A (`<kortnavn>-<name>`), `endringshash` (last table column, AN) and AD (`opprettet_av`, property `dct:creator`, = the scheme's `dct:creator` in B16) are formulas. AB `begrepseier` has the property `prov:Person`; persons are not converted to RDF. `endringshash` is 100 wide and not wrapped, so its long text does not make the rows tall. `tier` (AO) is the last column, outside the table; its header (row 21) describes tiers 1, 2 and 3. P is `skos:editorialNote`, Q `skos:scopeNote@nb`. Dropdowns for målgruppe (M), forhold til kilde (O) and status (AI) from the hidden sheet `lister`. No `kodeverk` sheet (dropped until the shared code lists are decided). |
| `SKOS-Excel-mal-v9-lang-ext.xlsx` | v9 + language extension | The master plus a `hovedspråk` row (B19) and columns AN–AW for en-US, en-GB, de and es labels and abbreviations, an en-US definition and an en-US scope note; `endringshash` AX, `tier` AY. Created with `vocabtool/template_ext.py`. |
| `SKOS-Excel-mal-v7.xlsx` | v7 (previous) | For reference and for testing `vocabtool migrate`. Rebuilt from the v7 layout: one sheet `<kortnavn>-vokabular` with the URI `vok:<Name>` in column A and relations as `vok:<Name>`, a `kodeverk` sheet, and the mapping table from step 1c (`mapping-oppsummering`). |

v9 has the same columns as v8; the tools read both. v9 adds the value lists, the B formula and the corrected AD formula.

Fill in the short name (`kortnavn`, letters, digits and hyphens, e.g. `N101`), the title and `dct:creator` first.
`python -m vocabtool fit <file>` stretches the table, the formulas and the dropdowns to all rows you use.

## Colours

Rows 20, 23 and 24 use the theme colours of the Vegvesen palette. Rows 20 and 23 follow the requirement level in
SKOS-AP-NO (row 20). Row 24 is orange also for columns that are obligatory in Statens vegvesen but not in SKOS-AP-NO
(M–P and AG–AI). The tools colour only the columns they add (language columns, `endringshash`); the template's own
columns keep their colours.

## Value lists and dropdowns

| Column | Dropdown values | Codes and URIs (sheet `lister`, named range) |
| --- | --- | --- |
| AI status | kandidat, gjeldende, utdatert, forkastet | EU concept-status CANDIDATE, CURRENT, DEPRECATED, RETIRED (`statusliste`) |
| M målgruppe | allmennheten, spesialist | data.norge.no audience-type public, specialist (`malgruppeliste`) |
| O forhold til kilde | basert på kilde, egendefinert, sitat fra kilde | relationship-with-source-type derived-from-source, self-composed, direct-from-source (`kildeforholdliste`) |
| `tier` (AO; AY in the language template) | 1, 2, 3 | – |

The dropdowns hold their values directly, not a reference to the `lister` sheet, so they still work when rows are
copied to another workbook or the hidden sheet is removed. The `lister` sheet documents the code and URI behind each
label. All of it is defined once in `vocabtool/lists.py`, and every tool that saves a workbook writes the dropdowns and
the `lister` sheet again. Reason: openpyxl, which the tools use, drops dropdowns stored in Excel's newer format.

A value outside the list gives a warning in Excel, not a block, so nynorsk or English codes (`basert på kjelde`,
`derived-from-source`) can still be entered; the checker accepts them, and the tools write them as the list label
(`sitat fra kilde`, `basert på kilde`) when they save the file, to match the dropdown and the SharePoint choice columns.
`tests/test_lists.py` checks the lists against the schema enums.
